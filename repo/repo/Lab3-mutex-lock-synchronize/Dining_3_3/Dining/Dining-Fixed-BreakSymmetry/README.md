# Dining Philosophers — Deadlock και Λύση

## Ο αρχικός κώδικας (`/Dining`) — γιατί μπλοκάρει

Στο `Philosopher.run()`, **όλοι** οι φιλόσοφοι κάνουν:
```java
right.get();   // πιάσε πρώτα το ΔΕΞΙ πιρούνι
left.get();    // μετά το ΑΡΙΣΤΕΡΟ
```

Αν όλοι οι φιλόσοφοι πιάσουν το δικό τους "δεξί" πιρούνι σχεδόν
ταυτόχρονα, τότε το "αριστερό" πιρούνι που χρειάζεται ο καθένας είναι
ήδη κρατημένο από τον διπλανό του (που το θεωρεί δικό του "δεξί").
Δημιουργείται μια **κυκλική αναμονή** (circular wait) — συνθήκη
απαραίτητη για deadlock. Κανείς δεν προχωράει ποτέ.

### Πώς να το δεις στην πράξη
Τρέξε το αρχικό `Diners.java`. Δοκίμασε:
- Να μειώσεις το `sleeptime` σε πολύ μικρή τιμή (π.χ. `1`) ή `0`,
  ώστε οι φιλόσοφοι να "τρέχουν" γρήγορα στο `right.get()` σχεδόν
  ταυτόχρονα -- αυξάνει την πιθανότητα deadlock.
- Να ξανα-ενεργοποιήσεις το commented-out `delay(scale);` πριν το
  `left.get()`, ώστε να δώσεις χρόνο σε ΟΛΟΥΣ τους φιλοσόφους να
  προλάβουν να πιάσουν το δεξί τους πιρούνι πριν κανείς προσπαθήσει
  για το αριστερό -- αυτό αυξάνει ΠΟΛΥ την πιθανότητα deadlock.
- Το πρόγραμμα θα "παγώσει": θα σταματήσει να τυπώνει οτιδήποτε,
  για πάντα (θα χρειαστεί να το τερματίσεις χειροκίνητα).

## Η λύση (`/Dining_Fixed`) — Σπάσιμο Συμμετρίας (Resource Ordering)

**Ιδέα**: αν όλοι οι φιλόσοφοι ακολουθούν την ΙΔΙΑ σειρά (πρώτα δεξί,
μετά αριστερό), υπάρχει πάντα κίνδυνος κυκλικής αναμονής. Αν όμως
**τουλάχιστον ένας** φιλόσοφος ακολουθεί **αντίστροφη** σειρά (πρώτα
αριστερό, μετά δεξί), ο κύκλος "σπάει" -- δεν μπορεί πια να σχηματιστεί
κλειστή αλυσίδα αναμονής.

### Τι άλλαξε
- **`Philosopher.java`**: προστέθηκε το πεδίο `reversedOrder`
  (true μόνο για τον ΤΕΛΕΥΤΑΙΟ φιλόσοφο, `identity == numphils-1`).
  Στο `run()`, αν `reversedOrder == true`, ο φιλόσοφος παίρνει πρώτα
  το αριστερό, μετά το δεξί πιρούνι -- όλοι οι υπόλοιποι κρατάνε την
  αρχική σειρά (δεξί, μετά αριστερό).
- **`Diners.java`**: μόνη αλλαγή -- περνάει `numphils` σαν επιπλέον
  όρισμα στον constructor του `Philosopher`, ώστε αυτός να μπορεί να
  υπολογίσει αν είναι ο "τελευταίος".
- **`Fork.java`**: καμία αλλαγή -- το πρόβλημα δεν ήταν στο πιρούνι/
  Lock, ήταν στη ΣΕΙΡΑ που τα ζητάνε οι φιλόσοφοι.

### Γιατί δουλεύει
Με 5 φιλοσόφους (0,1,2,3,4):
- Φιλόσοφοι 0,1,2,3: δεξί → αριστερό (ίδιο με πριν)
- Φιλόσοφος 4 (ο τελευταίος): αριστερό → δεξί (ανάστροφο)

Ο φιλόσοφος 4 θα προσπαθήσει πρώτα να πάρει το πιρούνι που ο
φιλόσοφος 3 θεωρεί "δικό του δεξί" -- δηλαδή ανταγωνίζεται με τον 3
για το ΙΔΙΟ πιρούνι που θα ζητούσε ούτως ή άλλως, αλλά ΤΩΡΑ δεν
δημιουργείται κύκλος: δεν υπάρχει πια σενάριο όπου ΟΛΟΙ κρατάνε από
ένα πιρούνι και περιμένουν κυκλικά το επόμενο -- κάπου η αλυσίδα
"σπάει".

### Πώς το επαληθεύεις
Τρέξε το `Dining_Fixed/Diners.java` με τις ΙΔΙΕΣ ρυθμίσεις (μικρό
sleeptime, ενεργοποιημένο delay) που προκαλούσαν deadlock στο
αρχικό -- το πρόγραμμα θα συνεχίσει να τυπώνει μηνύματα επ' άπειρον,
χωρίς ποτέ να "παγώσει".

## Εναλλακτικές λύσεις (για αναφορά / σύγκριση)

- **Ταξινόμηση πόρων με βάση ID**: κάθε φιλόσοφος πιάνει πρώτα το
  πιρούνι με το ΜΙΚΡΟΤΕΡΟ αριθμητικό ID (ανεξαρτήτως αν είναι το
  "αριστερό" ή το "δεξί" του) -- γενίκευση της παραπάνω ιδέας για N
  πόρους οποιουδήποτε τύπου.
- **`tryLock()` με timeout**: αν ένας φιλόσοφος δεν καταφέρει να
  πάρει και τα δύο πιρούνια μέσα σε συγκεκριμένο χρόνο, αφήνει ό,τι
  έχει πιάσει και ξαναδοκιμάζει αργότερα (αποφεύγει deadlock, αλλά
  εισάγει πιθανότητα livelock αν δεν υπάρχει τυχαιότητα στο retry).
- **Κεντρικός διαιτητής (arbitrator/waiter)**: ένα επιπλέον
  αντικείμενο-"σερβιτόρος" επιτρέπει σε το πολύ N-1 φιλοσόφους να
  προσπαθούν ταυτόχρονα να πιάσουν πιρούνια -- εγγυημένα αποτρέπει
  τον πλήρη κύκλο αναμονής, αφού τουλάχιστον ένας πάντα περιμένει
  εκτός.
